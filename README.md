# 家政服务临时取消与空跑费核算系统

客户临时取消订单时，**先看到可能产生的空跑费和完整计算依据，再决定是否提交取消**。
系统记录服务员出发、到场与客户取消的时间，使用**下单时锁定的规则快照**计费；
客服可对“是否到场”核对签到与定位后改判，改判保留原金额、调整结果与理由，双方可见；
账本只追加，锁账后只能追加补收/退款单；重复取消与退款重试只处理一次，金额始终与原订单对得上。

技术栈：Python · FastAPI · SQLAlchemy · SQLite · Vue 3（本地运行时，免构建）。

## 一条命令启动

```bash
./run.sh
# 打开 http://127.0.0.1:8000     前端
```

## 核心业务规则（下单即快照，之后改版不影响存量订单）

| 取消时服务员状态 | 结果 | 空跑费 |
| --- | --- | --- |
| 尚未出发 | 免收 | ¥0 |
| 已出发、未到场 | 空跑费 | 服务费 × 30%，最低 ¥20 |
| 已到场 | 空跑费 | 服务费 × 80%，最低 ¥50 |

- 距服务开始 ≥24 小时且服务员未出发免收；空跑费不超过服务费。
- 金额统一以**整数分**存储、计算，杜绝浮点误差。

## 关键设计如何满足需求

1. **取消预览在先、提交在后**
   `GET /api/orders/{id}/cancel/preview` 为只读，不落任何数据，返回金额与逐条依据
   （锁定规则版本、取消时状态、距开始时长、分档公式/最低费/封顶）。
   前端弹窗展示后，客户点“确认提交取消”才调用 `POST .../cancel`。

2. **出发临界时间：只认服务端事件顺序**
   每个订单有单调递增的事件流 `OrderEvent.seq`；取消时状态只由“取消事件之前、按 seq
   排序的服务端事件”决定，**客户端时间仅留档、不参与计费**。所有变更请求由单进程写锁串行化
   （`locking.write_locked`，单 worker 部署）。因此出发与取消几乎同时到达时，谁先在服务端
   落库谁生效，双方不可能各用客户端时间算出不同费用。见测试
   `test_critical_ordering.py` 与 `test_api_concurrency.py`。

3. **规则快照**
   `PricingRuleSnapshot` 在下单时把规则 JSON 固化到订单；费用引擎只读快照。

4. **到场争议与客服改判**
   围栏外签到或客户异议会把订单置为争议态，取消费用按保守档（已出发 30%）预估且暂不结算。
   客服在“签到与定位证据”表核对经纬度、距服务点距离、围栏判定后改判。
   每次 `Adjudication` 都记录 **from 金额/结果 → to 金额/结果、操作人、理由、时间**，
   系统原始判定（金额+依据）永不覆盖，客户与客服在同一详情页都能看到完整记录。

5. **扣费、退款分别入账；账本只追加**
   流水类型 `CHARGE`（收款）/ `FEE`（预付款划扣的空跑费）/ `REFUND`（退款）/
   `SURCHARGE`（补收），一行只记一件事，写入即不可改。
   - 已付款：预收款 `CHARGE`，空跑费以 `FEE` 划扣，余额 `REFUND` 退回；
   - 未付款：空跑费 `CHARGE` 收款。
   对账恒等式：`收款 + 补收 − 退款 = 最终费用（+锁后人工调整）`，详情页实时显示“对账一致/不平”。

6. **锁账**
   全部款项结清后可锁账。锁账后禁止改判，只能经 `/adjustments` **追加**补收(+)/退款(−)单，
   原有流水绝不修改。

7. **幂等与重试**
   - 取消单按订单唯一、并带幂等键：重复取消直接返回原结果，不再收费；
   - 模拟支付/退款网关按幂等键持久化（`PaymentAttempt`），成功后重试永远返回同一交易号；
   - 网关失败用 SAVEPOINT 回滚半截账本写入，只保留“取消/改判记录（failed）”，
     `POST /retry-settlement` 幂等重试，绝不重复扣款或重复退款。

## 目录结构

```
backend/
  app/
    main.py                 # FastAPI 路由（取消预览/确认、事件、争议、改判、锁账、重试、演示控制）
    models.py               # 订单/事件/证据/规则快照/取消/改判/账本/支付尝试
    schemas.py
    database.py             # SQLite + WAL + busy_timeout
    services/
      pricing.py            # 当前规则与下单快照
      fee_engine.py         # 纯函数费用引擎（状态判定 + 金额 + 可展示依据）
      cancellation_service.py # 编排：事件顺序、预览、取消、争议、改判、锁账、重试、序列化
      ledger.py             # 只追加账本、扣费/退款、改判找平、对账
      payment.py            # 模拟支付网关（幂等、可注入故障）
      geo.py                # 定位/围栏（haversine，模拟）
      clock.py              # 服务端可控时钟
      locking.py            # 变更请求串行化
  tests/                    # 22 个 pytest 用例
frontend/
  index.html  app.js  styles.css  vendor/vue.global.prod.js
run.sh                        # 一条命令启动
```

## 建议的手工演示路径

1. 创建一个**已预付**订单（默认 ¥300，3 小时后开始）。
2. 切到“服务员”点**出发**；切回“客户”点**取消订单**，先看到 ¥90（30%）与依据，再确认。
3. 用左下“演示控制”点**注入取消结算故障**，再走一次取消，可看到结算失败；
   切“客服”点**重试结算**，退款只发生一次，对账仍一致。
4. 新建订单 → 出发 → **围栏外签到**触发争议 → 客户取消显示“保守预估/待判定” →
   客服核对证据后改判。
5. 客服连续改判（90→240→免除），观察原金额始终保留、差额只以追加单找平；
   锁账后只能追加补收/退款，原账不变。
